# testbed: add scripts/wallets.sh

## Description

The accounting demo starts by generating wallets and printing their
addresses and viewing keys, so the user can paste one into the app UI.
Add a single idempotent script that runs the full setup and prints the keys.

## Design

`scripts/wallets.sh` (bash, `set -euo pipefail`, works from any dir):

```bash
./install.sh                       # .wallet1/.wallet2, deps, compile
./chain.sh                         # start anvil (idempotent)
./deploy.sh                        # deploy contracts + register vkeys
./op.sh create-wallets --names A,B # create wallets from the mnemonics
./op.sh export-keys                # write out/keys.json
jq -r 'to_entries[] | "\(.key)  \(.value.railgunAddress)\n  viewing key: \(.value.shareableViewingKey)\n"' ../out/keys.json
```

Why the full setup: `create-wallets` calls `startEngine()` →
`applyNetworkConfig()` → `readDeployment()`, which requires
`.state/deployment.json` to exist (i.e. the chain must be up and contracts
deployed first).

`out/keys.json` shape (`demo/src/lib.ts exportKeys()`):

```json
{ "B": { "railgunAddress": "0zk…", "shareableViewingKey": "…",
         "viewingPrivateKey": "0x…", "creationBlock": 0 } }
```

- `shareableViewingKey` is a hex string (from `getWalletShareableViewingKey`);
  this is what the user pastes into the app.
- Idempotent: re-running skips install/chain/deploy/wallet creation.
- Does NOT write `out/steps.jsonl`, so `scenario.sh` can still run afterwards.

Update `docs/testbed/spec.md` (Scripts section + repo layout).

## Acceptance Criteria

- Running `scripts/wallets.sh` on a fresh clone prints A and B, each with
  `0zk…` address and a shareable viewing key.
- Re-running prints `skip:` lines only.
- `out/keys.json` exists with both wallets.
- Running it a second time does not touch `out/steps.jsonl`.
